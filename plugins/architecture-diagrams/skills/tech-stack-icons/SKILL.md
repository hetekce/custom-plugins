# Tech stack icons

Turn each node's `tech` slug into an `icon` token before rendering. How you do
that depends on the output format.

## Mermaid — reference, never rasterize

Mermaid loads Iconify packs natively, so `node.icon` is just an Iconify id:

```bash
node ${CLAUDE_PLUGIN_ROOT}/scripts/fetch-icon.mjs postgresql --format iconify
# -> logos:postgresql
```

No network call, no image file. The mermaid-diagrams skill passes
`--iconPacks @iconify-json/logos` to mmdc and uses the id directly:
`service db(logos:postgresql)[Orders DB]` in architecture-beta, or
`n1@{ icon: "logos:aws-lambda", ... }` in flowcharts.

## draw.io and Gliffy — embed a PNG

These formats need real image data so the file stays self-contained:

```bash
# data URI for a draw.io shape=image cell (default format)
node ${CLAUDE_PLUGIN_ROOT}/scripts/fetch-icon.mjs kafka --size 256

# or a PNG file on disk
node ${CLAUDE_PLUGIN_ROOT}/scripts/fetch-icon.mjs kafka --size 256 --format png --out icons/kafka.png
```

The script fetches the SVG, rasterizes it (prefers `resvg`, falls back to
`rsvg-convert`), and caches the result by (slug, size). If neither rasterizer
is installed it warns and emits the SVG instead — draw.io accepts
`data:image/svg+xml` data URIs, so that is still usable.

## Bundled set — offline first

Around 250 common icons ship pre-rasterized under `assets/icons/` (SVG + PNG at
128 and 256 px), generated by `scripts/build-icons.mjs`. `fetch-icon.mjs` serves
these first, so the usual data-engineering, data-science, and software stack
renders with no network call and identical output every time. See
`assets/icons/manifest.json` for what is bundled and `assets/icons/GAPS.md` for
the few tools with no permissively licensed icon.

## Source priority

1. Bundled set (`assets/icons/`) — offline, deterministic
2. Iconify `logos` collection (CC0) — colored brand marks, best quality
3. Devicon (MIT)
4. Simple Icons (CC0) — flat single-color marks, matched by slug

Never use the official AWS, Azure, or GCP icon sets — their terms of use do
not allow redistribution. The CC0/MIT collections above cover the same
services (`logos:aws-lambda`, `logos:google-cloud`, `logos:microsoft-azure`).

Unknown slug? Search https://icones.js.org and pass the full id — a slug
containing `:` (for example `devicon:neo4j`) is used as-is.

## Role defaults — when a node has no tech logo

Nodes like an actor, an external system, or a plain gateway have no brand logo.
Give them a modern, consistent icon by `role` from
`assets/icons/role-defaults.json` (clean Lucide line icons, also bundled):

| role | icon | | role | icon |
| --- | --- | --- | --- | --- |
| actor | `lucide:circle-user-round` | | datastore | `lucide:database` |
| client | `lucide:monitor` | | cache | `lucide:zap` |
| service | `lucide:box` | | queue | `lucide:list-ordered` |
| gateway | `lucide:route` | | external | `lucide:globe` |
| job | `lucide:cog` | | | |

Mermaid uses the id directly (the `lucide` pack is registered); draw.io and
Gliffy resolve it through the same `fetch-icon.mjs` call, which finds the
bundled copy.
